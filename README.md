# 小米万兆路由器 · 流量监控

通过 SSH 采集小米万兆路由器（OpenWrt 固件）的实时与历史流量，在 Windows 本地用浏览器查看总流量趋势、各设备上下行统计、设备访问的服务，并支持任意时间段的历史查询。

> **AI 生成声明**
> 本项目代码由 **DeepSeek** 生成，经人工审查、在真实设备上反复实测后交付。
> 生成内容已在以下方面逐项复核：SSH 协议与算法兼容性、conntrack 采集口径的正确性与重复计数、计数器归零与读取截断等边界情况、凭据与隐私处理。
> 使用前请自行评估风险：本工具会通过 SSH 以 root 身份读取路由器内核状态，**请自行确认可接受**，并建议仅在可信内网使用。
> 仓库内**不含任何真实凭据、IP、设备名或抓取数据**，连接信息需由使用者自行填写。

## 一、快速开始（exe 版）

双击 **`路由器流量监控.exe`**，出现一个小窗口，只有两个按钮：

| 按钮 | 行为 |
|---|---|
| **开机自启：已关闭（点击开启）** | 开关。开启后向注册表 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 写入启动项（值为 `"exe路径" --server`），下次登录静默在后台采集，不弹窗。可在「任务管理器 → 启动」里看到并禁用。 |
| **打开监控页面** | 确保后台服务在跑（没跑就自动拉起，约 2 秒），然后打开浏览器 `http://127.0.0.1:8787/`。 |

- 程序启动时会自动拉起后台服务，窗口里那行状态实时显示 `运行中 · 已连接路由器 · ↓ xx KB/s ↑ xx KB/s`。
- **关闭窗口不会中断监控**：会问一句「是否同时停止后台监控服务」，选「否」则监控继续在后台跑，浏览器随时能看。
- 配置和数据都在 exe **同级目录**：`config.json`（可编辑）、`data\traffic.db`（历史数据）、`data\monitor.log`（后台日志）。整个文件夹可以直接拷到别的机器。
- 第一次运行如果被 Windows SmartScreen 拦下（未签名程序常见），点「更多信息 → 仍要运行」；杀软误报同理加白名单。

命令行方式（源码运行，调试用）：

```bash
pip install -r requirements.txt
python app.py                 # 默认 127.0.0.1:8787，自动开浏览器
python app.py --port 9000     # 换端口
python launcher.py            # 带界面的启动器（开发模式）
```

> 前提：路由器已开启 SSH（`root` / 密码见 `config.json`），且本机与路由器在同一网段。

## 三、数据从哪来

路由器是 OpenWrt 18.06（aarch64），**没有** `nlbwmon` / `vnstat`，所以两路数据分开取：

| 指标 | 来源 | 说明 |
|---|---|---|
| WAN 总流量 | `/proc/net/dev` 的 `pppoe-wan` 累计计数器，做差值 | 精确，不受连接老化影响 |
| 各设备流量 | `conntrack -L -o extended` 的字节计数器，逐连接做增量 | 路由器无按主机记账，只能靠 conntrack 推算 |
| 设备档案 | `/tmp/dhcp.leases`、`ip neigh`、`iwinfo assoclist` | 主机名、MAC、有线/无线、频段、信号 |
| WAN/LAN IP | `ip route`、`ip -4 -o addr` | 自动识别 WAN 接口（PPPoE 为 `pppoe-wan`） |

每轮采集只发**一条** SSH 命令（脚本内批量取回全部数据并打分隔符），实测单轮耗时约 0.06 秒、约 50 KB。

### 精度实测

| 场景 | 下行偏差 | 上行偏差 |
|---|---|---|
| 10 秒采样（连续 6 轮） | -0.0% ~ -0.7% | -0.2% ~ +2.4% |
| 60 秒采样 | -0.5% | -6.1% |

误差来自 conntrack 采样机制本身：连接在两轮采样之间关闭，最后一段字节会丢失；新连接按全量计入。采样间隔越短，设备明细越精细，但相对误差也会变大；**总量以 WAN 计数器为准，不受影响**。

## 三·五、服务识别能做到什么，做不到什么

**先说结论：本工具不提供"具体网站域名"，只提供"目标服务/地址"级识别。**

这不是偷懒，是在目标固件上逐项验证后的结果：

| 方案 | 实测结果 | 结论 |
|---|---|---|
| dnsmasq 查询日志 | 未开启 `log-queries`，`logread` 里 0 条 | 需改路由器配置，不采用 |
| 反向 DNS（PTR） | 命中率 16%，命中多为 `unassigned.xxx` 之类无意义结果，且单次失败等 4.7 秒 | 不可用 |
| TLS SNI 抓包 | 路由器有 tcpdump，但当前流量以 QUIC(UDP/443) 为主，SNI 不可见；全量过包在 10G 路由器上 CPU 风险高 | 不采用 |
| 路由器上的代理 API | 端口被占用、无响应，且只覆盖代理流量 | 不可依赖 |
| **conntrack 的「目的 IP + 端口」** | 每轮已在采集，零额外开销 | **采用** |

因此服务名称按四级推断，界面上会标注来源：

1. **自定义** —— 你在界面上给某个 IP 命的名，优先级最高
2. **推断** —— 命中内置的已知服务网段（如 Cloudflare / Google / 腾讯），**只代表 IP 归属该网段，不代表一定是该服务**
3. **端口** —— 按端口语义（HTTPS / QUIC / DNS / NTP / STUN …）
4. **未知** —— 显示 `IP:端口`

想让名称准确，就用明细里的「命名」把常用地址标成自己的叫法，规则写进 `config.json` 的 `service_overrides`，立刻生效。

**开销实测**（200 条连接的完整解析 + 服务聚合）：

| 指标 | 数值 |
|---|---|
| 单轮 CPU 增量 | **1.78 ms**（同一轮 SSH 往返为 60 ms 量级，占比约 3%） |
| 名称解析（缓存命中） | 0.001 ms/次 |
| 额外 SSH 流量 | 0（复用已有 conntrack 数据） |
| 存储增长 | 每设备每天最多 20 条，约 30 KB/天 |

## 四、踩过的两个坑（已处理）

**1. paramiko 版本必须锁 3.4.1**

路由器 Dropbear 只提供 `ssh-rsa` 主机密钥 + `aes128-ctr`，paramiko 4.0 起彻底移除 `ssh-rsa`，5.x 会直接报 `Incompatible ssh peer (no acceptable host key)`。

```bash
pip install "paramiko==3.4.1"     # 不要 --upgrade
```

`requirements.txt` 已锁定，`启动监控.bat` 会自动检测并修复。

**2. `/proc/net/nf_conntrack` 会被截断**

它是 seq_file，高并发下 `cat` 出来的条目数会少于实际（实测 156 条 vs 实际 168 条）。漏掉的连接下一轮会被当成"新连接"全量计入，导致设备流量虚高 60%+。改用 netlink 接口 `conntrack -L -o extended` 后完全一致（155/155、141/141…），并加入一致性校验：读到的条目数 < 内核 `nf_conntrack_count` 的 85% 时，本轮直接跳过设备统计并重新建立基线。

**3. 透明代理会导致重复计数**

路由器上跑着 ShellCrash（fake-IP 段 `198.18.0.0/15`），TPROXY 保留客户端源 IP，同一份流量在 conntrack 里会出现两条（客户端→fake-IP、代理→真实 IP）。`config.json` 里的 `ignore_peer_cidrs` 用于排除这类对端，实测过滤前下行偏差 +67%，过滤后归零。

> 如果你换用其他代理（Clash/sing-box 等）且 fake-IP 段不同，把对应网段加进 `ignore_peer_cidrs` 即可。

## 五、配置（config.json）

**仓库里不带凭据。** `config.json` 被 git 忽略，首次运行 exe 会弹出配置窗口要求填写路由器地址、SSH 用户名和密码，写入本地 `config.json`（仅在你的机器上）。字段说明见 `config.example.json`。

```jsonc
{
  "router": { "host": "", "port": 22, "username": "root", "password": "" },  // 必填，密码不随代码分发
  "poll_interval": 10,              // 采集间隔（秒），3~300
  "wan_iface": "",                  // 留空自动识别，PPPoE 填 "pppoe-wan"
  "lan_subnets": ["192.168.31.0/24"],           // 你的内网网段，有访客/物联网子网就都加上
  "ignore_peer_cidrs": ["198.18.0.0/15"],       // 代理 fake-IP 段，不计入设备流量
  "service_overrides": {},                      // 服务命名表：{"1.2.3.4": "我的 NAS"} 或 {"1.2.3.0/24": "公司"}
  "http": { "host": "127.0.0.1", "port": 8787, "open_browser": true },
  "storage": { "db": "data/traffic.db", "keep_days": 90, "keep_raw_hours": 24 }
}
```

改完重启程序生效；采集间隔与保留天数也可以在界面「设置」里热改（会写回本文件）。
服务命名在「服务」页里点「命名」即可，等价于往 `service_overrides` 写一条。

`lan_subnets` 决定了什么算"内网"：只有一端在内网、另一端在外网的连接才计为 WAN 流量，内网互访（NAS、投屏、备份）不计入。

> 安全提示：`config.json` 里是明文密码。请勿把该文件提交到任何仓库（`.gitignore` 已排除），
> 也建议用一个专用的低权限 SSH 账号，或在用完后关闭路由器 SSH。

## 六、数据存储

SQLite，`data/traffic.db`，WAL 模式：

| 表 | 粒度 | 保留 |
|---|---|---|
| `wan_10s` | 每轮一条（实时曲线） | 24 小时 |
| `wan_minute` | 分钟聚合（长周期趋势） | `keep_days`（默认 90 天） |
| `dev_5min` | 每设备 5 分钟聚合 | 默认 45 天 |
| `svc_day` | 每设备每天的服务 Top 20 | 随 `keep_days` |
| `devices` | 设备档案（IP/主机名/厂商/接入方式） | 永久 |
| `events` | 断线、计数器归零等事件 | 30 天 |

- 90 天分钟级数据约 13 万行 / 20 MB，每天自动清理。
- 重启程序不丢数据；历史累计从**首次运行**开始，路由器自身的 63 天历史无法回溯（固件不保存按设备的历史）。

## 七、常见问题

**状态灯一直是"连接中断"**
1. 看「诊断」页的"最近错误"，错误信息已翻译成中文（超时 / 拒绝 / 认证失败 / 算法不兼容）。
2. `ping 192.168.31.1` 是否通；确认路由器 SSH 已开启（小米需在后台开启 SSH 并知道 root 密码）。
3. 换过网络后本机 IP 变了，同网段才能连。

**设备列表为空 / 流量全是 0**
- 检查 `lan_subnets` 是否覆盖你家的网段（例如路由器改成了 `192.168.2.0/24`）。
- 设备流量依赖 conntrack，若路由器上执行 `conntrack -L` 无输出，说明 conntrack 内核模块未加载。

**某台设备流量明显偏大**
- 大概率是代理导致的重复计数，把代理的 fake-IP 段加进 `ignore_peer_cidrs`。

**路由器重启后数据跳变**
- WAN 计数器归零会被检测到，本轮差值按 0 处理，并在「诊断」里记一条"计数器归零"事件，不会产生假峰值。

**想开机自启**
- 直接点窗口里的「开机自启」按钮，写的是当前用户注册表 `Run` 项，登录后静默启动（无窗口）。
- 取消：再点一次；或在「任务管理器 → 启动」里禁用 `XiaoMiRouterTraffic`。
- 源码方式（用 bat）想自启，可 `Win+R` → `shell:startup` 放快捷方式，或任务计划程序。

**exe 打不开 / 一闪而过**
- 看 `data\monitor.log`（后台服务日志）。
- 若是 SmartScreen 拦截：更多信息 → 仍要运行。
- 若提示端口被占用，说明已有一个实例在跑，直接访问 `http://127.0.0.1:8787/` 即可。

**关掉窗口后网页连不上、弹 "Failed to remove temporary directory"**
- 这是 onefile 打包的经典坑：GUI 拉起的子进程继承了 PyInstaller 的解包目录变量，两个进程共用一个 `_MEIxxxx` 临时目录，父进程一退出就把目录删了，后台服务的文件随之消失。
- 已修复（清空 `_PYI*`/`_MEI*` 环境变量，让子进程解包到自己目录）。如果你手上是旧版本，直接换成当前 exe。
- 万一遇到类似"端口通但页面打不开"的僵死状态，点一下窗口里的「打开监控页面」会自动检测并重启后台服务。

### 重新打包 exe

```bash
pip install pyinstaller "paramiko==3.4.1"
pyinstaller --noconfirm --onefile --noconsole ^
  --name "路由器流量监控" --icon icon.ico ^
  --add-data "web;web" --add-data "icon.ico;." ^
  --hidden-import app --hidden-import collector ^
  --hidden-import storage --hidden-import router_client ^
  launcher.py
```

要点：`app.py` 里区分了 `_MEIPASS`（打包后的静态资源临时目录）和 `sys.executable` 所在目录（配置与数据），否则打包后配置和数据库会写进临时目录、重启就丢。

前端不依赖任何 CDN，断网也能正常显示。

## 九、已知限制

- 按设备统计从工具首次运行开始累计，无法回溯路由器开机以来的历史。
- **服务识别只到"目标 IP + 端口"级别，给不出具体域名**（原因见第三·五节）。标「推断」的名称仅表示 IP 归属某网段。
- 服务的历史数据按天聚合、每设备只存 Top 20，适合看"主要在用哪些服务"，不适合做逐条连接的审计。
- 设备识别依赖 DHCP 租约和 ARP 表；使用 MAC 随机化的设备（如部分手机）在重连后可能显示为新设备。
- 仅统计 IPv4；IPv6 连接不计入设备与服务明细（WAN 总量仍包含）。
- 设备流量为采样推算，适合看趋势和排行，不适合当作计费级精确账单。
